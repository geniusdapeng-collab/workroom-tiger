## 第一部分：理论体系校验（任务一）

### 1.1 总体结论

MRS/SHS/TSS 三道门的分层设计在逻辑上是自洽的：大盘管仓位（能不能做）、板块管方向
（做什么）、个股管买点（怎么做），配合一致性修正 k 抑制"单维度失真"，整体框架
符合 1-15 天波段的交易现实。理论本身可以成立，但存在以下需要完善的点。

### 1.2 需要完善的问题清单

**T1 · 三道门之间的耦合关系缺少形式化定义。**
理论规定了"AND 门"（MRS≥6 且 SHS≥7.5 且 TSS≥7.2 才标准做多），但没有定义
"边界态"的处理优先级。v4.0 补全：轻仓试错通道（MRS* 4-6 且 TSS≥7.8，仓位×0.35）
与 AVOID（MRS*<4）形成完备的三态划分，消除了原理论中 MRS*∈[4,6) 且 TSS<7.8
时的未定义区域。

**T2 · 一致性修正的 Δ 定义在理论文档与代码间不一致。**
理论定义 Δ = 五维评分极差（max−min），旧代码实现用的是标准差。二者在评分呈
双峰分布时差异巨大（如 [9,9,2,2,2]：极差=7→k=0.5，标准差≈3.4→按旧代码误判
为一致）。v4.0 已按理论的极差定义修正，阈值分段 Δ<4 / 4≤Δ≤6 / Δ>6 不变。

**T3 · VIX 极低档的"脆弱性平静"设计需要在文档中显式化。**
映射表对 VIX≤13 只给 7 分而非满分，这是一个有意的反直觉设计（极低波动往往
对应拥挤多头与脆弱结构）。建议理论文档将其列为正式设计条款而非映射表特例，
否则后续维护者容易当成 bug "修复"掉。v4.0 已在 indicators.py 中以注释固化。

**T4 · 缺少产业链周期维度（用户指定新增）。**
原理论板块分析止步于 SHS 的行业热度，无法刻画"同一产业链上中下游的利润传导
与轮动节奏"。v4.0 新增 ICS 模块（见第四部分），作为 Layer2b 嵌入，与 SHS 正交：
SHS 回答"哪个板块热"，ICS 回答"这条链处于周期哪个阶段、利润正在哪个环节"。

**T5 · 时间止损与事件驱动的衔接规则空缺。**
理论规定 5-7 日时间止损，但未规定"持仓中遭遇财报/FOMC/CPI"的处理。v4.0 在
RiskManager 的交易卡片中加入事件日历字段与"重大事件前减仓至半仓"的默认规则。

**T6 · WFA 与 DSR 的统计严谨性（P2 级）。**
理论引用的 Walk-Forward Analysis 在旧实现中是简化版（单次前后切分），并非真实
的滚动前推；DSR（Deflated Sharpe Ratio）实现也未完整考虑多重检验次数的估计。
这两项影响的是"策略评估"而非"盘中信号"，v4.0 在报告中如实标注为 P2 待办，
不影响当前交易流程的正确性。

## 第三部分：旧系统"总是同样几只股票"根因诊断（任务三）

### 3.1 现象

无论市场如何变化，系统每次运行输出的标的物几乎固定在
AAPL / MSFT / GOOGL / NVDA / TSLA / AMD / META / AMZN 这几只。

### 3.2 根因清单（按贡献度排序）

**R1 · engine.py 两处硬编码 watchlist（根因中的根因）。**
第 495 行与第 878 行各有一份
`default_watchlist = ["AAPL","MSFT","GOOGL","NVDA","TSLA","AMD","META","AMZN","SPY","QQQ"]`。
无论上游 Agent 产出什么，执行层在 watchlist 为空或解析失败时都会回退到这 10 只
（还混入 SPY/QQQ 两个 ETF，它们不是可交易标的）。

**R2 · Stock-Selector 的候选从未回流。**
StockSelectorAgent 在 Layer 4 内部对候选打分，但结果从未写回
`context["watchlist"]`，下一轮循环仍从硬编码清单出发——即使它选对了，系统也
"记不住"。

**R3 · 系统根本没有全市场扫描机制。**
整条流水线没有任何一个环节负责"从几千只美股里筛出候选池"。没有输入端，
输出端自然永远是那几只。

**R4 · 搜索链路静默失效。**
`utils/search.py` 依赖 search_cli.js / fetch_cli.js，这两个文件不在仓库内，
调用失败后静默返回空列表 → 所有依赖新闻/叙事的 Agent 拿不到数据 → 全部回退
默认分。失败没有任何告警，表现为"系统正常但结果不变"。

**R5 · 最终选股靠正则解析 evidence 字符串。**
`_extract_ticker` 按 known_tickers 列表顺序在文本中找匹配——列表顺序就是
AAPL 在前，于是只要 evidence 里同时出现多个代码，永远选中靠前的；正则回退
还会把 "AI"、"NOW" 这类词误识别为股票代码。

**R6 · 评分是"关键词命中计数"的伪量化。**
composite_score 对每只股票统计新闻关键词命中数，由于 R4 搜索为空，所有股票
得分完全相同 → 排序不稳定 → 进一步放大 R5 的顺序偏差。

### 3.3 v4.0 的修复对应

| 根因 | 修复 |
|---|---|
| R1 | 删除全部硬编码清单，Layer0 UniverseScannerAgent 全市场扫描产生候选 |
| R2 | 候选池作为一等公民在 context 中显式传递，每轮由扫描器重建 |
| R3 | 新增扫描器：硬过滤（价≥$5、ADV≥$20M、历史≥260日、ATR%≤12%）+ 量化初排（RS63分位30%+RS20分位25%+均线结构20%+波动收缩15%+近新高10%） |
| R4 | 移除外部 CLI 依赖；所有数据缺失走显式降级路径并在报告"缺失披露"区列出 |
| R5 | 全流程结构化字段（ticker 作为 dataclass 字段直传），零文本解析 |
| R6 | 评分全部来自真实 OHLCV 的映射表计算，单元测试锁定区分度 |

## 第四部分：新增模块——产业链周期 ICS

### 4.1 设计动机

SHS 告诉你"半导体板块热"，但不告诉你这条链的利润正在从上游设备向中游代工
传导、还是已经在下游应用端过热。ICS 把产业链当作分析对象，补足这个维度。

### 4.2 公式

```
ICS = 0.30×链RS强度 + 0.25×链内广度 + 0.25×环节轮动 + 0.20×周期阶段
```

- **链RS强度**：链内各环节代表标的相对 SPY 的 63 日相对强度分位加总
- **链内广度**：链内成分股站上 50 日线的比例（0-10 映射）
- **环节轮动**：中游领涨→9（主升特征）；上游领涨→8（传导初期）；下游补涨且
  龙头滞涨→3（行情尾声特征）
- **周期阶段**：复苏 7 / 扩张 9 / 过热 4 / 衰退 2，由链RS趋势与广度联合分类

### 4.3 与三道门的衔接

ICS 不推翻三道门，只做一个**乘性修正**：
热区链（ICS≥7.0）内标的 TSS_final = TSS×bonus（bonus≤1.15）；
衰退链（ICS<4.0）内标的 ×0.95。加成本身不改变闸门阈值，避免双重计数。

### 4.4 内置链覆盖

8 条链：半导体、AI 算力、电动车、金融科技、能源、生物科技、核能、消费，
每条链定义上游/中游/下游代表标的与跟踪 ETF，支持 TICKER→CHAIN 反查与
SECTOR→CHAINS 映射（chains.py）。

# 第六部分：v4.1 落地执行报告（P1/P2/P3 + 自我迭代闭环）

日期：2026-07-30
目标：把 v4.0 的全部待办逐项执行，让系统真正跑起来、可结算、可追踪胜率、可持续自我改进。

## 6.1 核心校准：缺失因子再归一化（修复"闸门被暗中焊死"）

**症状**：v4.0 上线后回测 204 个信号日仅放行个位数交易日，深挖发现 SHS 主线池
**0 天**——叙事（EPS 修正/指引）与微观（GEX/0DTE/Skew）两个免费源永远缺失，
旧实现把它们钉在中性 5 分：SHS = 0.25×宏观 + 0.35×资金 + 0.25×5 + 0.15×5，
即使宏观/资金双满分，上限也只有 ≈6.5，永远够不到 7.5 的主线阈值。MRS、TSS
同理。三道门在免费数据下被"中性分"暗中焊死。

**修法**：全链路改为"缺失即 None"——数据模型 `DimensionScore.score` 与
`StockCandidate.s_options` 改 Optional；各 Agent 缺数据时传 None 而非 5；
`indicators.aggregate` 重写：剔除 None/NaN 后按剩余权重再归一化
（`val = Σwᵢsᵢ / Σwᵢ`，全缺失才回退中性分）。Δ（一致性极差）只在可用维度上计算。

**效果**（同一 demo 数据、同一闸门）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| SHS 主线池天数 | 0 / 204 | 126 / 204 |
| 标准做多放行天数 | ≈3 / 204 | 60 / 204 |
| 回测成交笔数 | 4–9 笔 | 59 笔（≈2–3 笔/周，符合 1-15 天波段频率） |

这不是放松闸门，而是让闸门恢复到理论设计的选择性：主线该出现时能出现，
不该出现时仍然封死（震荡日 MRS*<4 → AVOID 的逻辑不受影响）。

## 6.2 P1 · 真实全市场 Universe（universe.py）

- 接入 NASDAQ Trader 官方 symdir 清单（nasdaqlisted + otherlisted，管道分隔），
  过滤 Test Issue / ETF / 权证 / 单位 / 优先股，符号转 Yahoo 风格（`BRK/B`→`BRK-B`）；

## 6.3 P2 · 无未来函数回测（backtest.py）

三层架构，把"参数无关的重型计算"与"闸门参数回放"分离，支撑后面的大规模调参：

1. `collect_day_frames`：逐信号日切 ≤t 的 310 行数据，跑真实 MRS/Sector/Chain
   Agent 与 TSS 精评（含 TopN + 主线定向补扫），产出 DayFrame；帧级 pickle 缓存，
   二次运行秒级；
2. `run_backtest(GateParams)`：在帧缓存上回放三层闸门，次日开盘价入场
   （最多等 3 日，开盘直接破止损则放弃），止损优先保守假设，浮盈 ≥2R 止损上移至
   +0.5R，7 日时间止损收盘平仓，跳空按开盘价成交；
3. `run_wfa`：滚动前推调参（见 6.4）。

无未来函数由三条独立测试锁定：入场日 > 信号日；出场日 ≥ 入场日；
**篡改信号日之后的数据，当日评分逐位不变**（切片隔离测试）。

## 6.4 P2 · 滚动 WFA + 完整 DSR（stats.py / backtest.run_wfa）

- 滚动前推：train 126 日 / test 63 日 / step 63 日；折内对 27 组闸门网格
  （OPEN_LONG × SHS_MAIN_POOL × TSS 阈值）选期望 R 最优，折外（OOS）拼接验证；
- DSR（Bailey & López de Prado 2014）：PSR + E[max_N SR] 多重检验校正，
  试验次数取 网格 27 × 折数（保守上界），纯 stdlib `statistics.NormalDist` 实现；
- 产出 `tuned_params.json`，`pipeline.apply_tuned_params()` 次日自动覆盖闸门并留痕。

**Demo 复验结果**（380 日、3 折、OOS 114 笔）：OOS 胜率 46.5%、期望 −0.11R、
**DSR = 0.000 → 不显著，系统正确地拒绝过拟合、保持理论默认参数**
（折内"最优"参数 IS 夏普 3.92 → OOS 期望转负，正是多重检验下的典型过拟合；
同期默认参数全样本回测 187 笔、胜率 51.9%、期望 +0.077R、利润因子 1.21——
默认参数反而更优，DSR 校正保护了它不被覆盖）。
这验证了调参闭环的诚实性：它不会为了在随机数据上"显得有效"而硬造参数。
真实数据建议 `--bt-days 560` 以上（AD20 分位需要 ≥505 日历史才会出现，
不足时该因子按 6.1 规则剔除再归一化，诚实处理）。

## 6.6 P3 · 盘前/盘中触发器（triggers.py / journal.py）

- `premarket_plan`：盘前作战计划（候选清单 + 入场触发价 + 止损 + 放弃条件）；
- `monitor_once / monitor_loop`：盘中轮询，ENTRY（距入场价 ±0.5%）、STOP
  （触及止损）、PROTECT（浮盈 ≥2R 提示上移止损）三类警报，`triggered` 集合去重；
- `journal`：信号落账（去重）→ 次日按回测同规则真实结算 → 累计/近 20/近 50
  胜率、期望 R、分模板统计，日报新增"九、胜率追踪"小节。至此闭环成形：
  **信号 → 落账 → 结算 → 胜率 → WFA 调参 → DSR 校正 → 次日生效**。

## 6.7 主线定向补扫 + 第九条产业链（industrials）

- 问题：全局 TopN 初排可能把主线板块内的强结构票挤出去（板块热但个股绝对分

# 第七部分：v5.0 信息层重构（系统核心优化指令全量落地）

日期：2026-07-30

## 7.1 搜索集成模块（search/）

- **SearchHub**：6 源线程池并发 + 内存/磁盘双级 TTL 缓存（6h）+
  每源独立超时 + **总墙钟预算**（45s，慢源到点切断记失败）+
  **熔断器**（连续 3 败冷却 15 分钟）；
- **横向广度**：agent-gw 全网实时搜索（多语言查询词规划）、Google News RSS、
  Reddit 小众论坛（stocks/wallstreetbets/investing）；
- **纵向穿透**（竞品看不见的"蛛丝马迹"）：
  SEC EDGAR 全文检索（8-K 供应链扰动/客户集中度变更）、
  PatentsView 专利 API、FederalRegister 联邦公报（出口管制/补贴等政策微调）；
- 实测（沙箱）：kimi_search 与 federal_register 稳定可用，reddit 慢源被墙钟
  正确切断，单源故障零阻塞。

## 7.2 数据清洗 LLM 化（cleaning/）

严格按指令划界：规则只保留去重（doc_id + 内容指纹近似去重）与格式校验
（Unicode 归一/截断/过短剔除）；**实体消歧、情感分析、事件抽取、关联推断
全部 LLM**。pytest 行为测试 + 源码静态审查双重锁定：LLM 全灭时输出只能
全 degraded，绝无任何规则补算的语义字段；模块内禁止出现情感词典。

## 九、v5.3 行情源根修 + 投资者业务语言报告（2026-07-30）

### 行情源限流根修（agentgw 服务端通道）
- 根因：直连 yfinance 从本地出口 IP 抓 Yahoo 网页接口，共享出口 IP 触发
  YFRateLimitError；stooq 走本地 HTTP 出口，受限网络大面积超时——属环境性常态问题。
- 根修：新增 `providers/agentgw.py`——经 agent-gw 服务端调 yahoo_finance 数据源的
  get_historical_stock_prices，请求在服务端发出，不经过本地出口 IP。
  降级链升级为 **yahoo → stooq → agentgw**（单只/批量同构），也可 `--provider agentgw` 指定。
- 特性：2 年日线（覆盖 420 交易日需求）；^TNX 单位自适配（×10 口径/真实收益率）；
  4 路并发 + 240s 墙钟；本轮内存缓存（零基线：不落盘、不跨轮）。
- 实证：yahoo/stooq 全挂环境下 `--provider agentgw --universe core` 独立跑完
  真实全链路（17 环节全执行，覆盖 191/224，444.6s，MRS*=3.38 负向共振→AVOID，
  主线 XLF/XLE——真实数据真实结论）。

### 投资者业务语言报告（核心机密保护）
- 决策卡五段依据全部业务化：市场环境体检/板块选择理由/产业链景气/个股质地/
  交易计划与风控 + 失效与离场条件；删除全部计算公式、权重、阈值参数、内部排序分(TOS)。
- 章节业务改名：市场环境体检/板块热度地图/产业链景气周期/个股精选清单/
  交易计划与风控纪律/系统执行自检；雷达图维度中文化。
