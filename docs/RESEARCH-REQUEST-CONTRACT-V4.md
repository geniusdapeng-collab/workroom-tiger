# Research request contract for budget policy v4

This change exposes existing research validation rules in the request before a
model generates a thesis. It applies to `tiger.budget-policy.v4` research initial
assessment, supplemental final assessment, and final decision. It does not amend
model output or relax the existing source, quote, time, numerical-risk, or
paper-account validators.

The motivating run, FULL16, remains failed. Its saved non-text field projection
contains 10 theses and 59 claims: 3 stock sections omit their own market evidence,
46 Search claims use an invalid date-source reference, and 26 claims mark evidence
older than seven days as current. These classes overlap. The regression checks
each original field predicate separately; it does not turn that run into a
successful receipt or replace its actual answers with synthetic answers.

## Scope and compatibility

The source baseline is `b304991727e9230cb42732de3a1791ae9fa54918`. The request
branch is selected by the existing execution policy's exact budget policy ID.
Calls with no policy, v2, or v3 continue using their original schema builders and
payloads. A synthetic golden generated by the unmodified baseline binds the
complete canonical research requests, decision requests, outputs, and native
call plans for all three legacy profiles. It is an offline regression artifact,
not a stored model response from production.

The v4 change adds `request_bindings` to the original payload. Every original
payload field remains. It leaves source text allocation, full-source metadata,
input truncation markers, clean output handling, maximum output tokens, budget
policy, call counts, model selection, thinking configuration, and semantic
authority unchanged. The normal request budget calculation includes the entire
new guide and schema. A request that exceeds an unchanged budget still fails.

## Deterministic guide

`candidate_research.build_thesis_binding_guide` accepts the exact symbols,
observed documents, fact and market evidence, frozen assessment, phase, and
per-symbol presentation history. Initial requests also supply the existing
supplemental query templates. It returns `tiger.thesis-request-bindings.v1`:

| Field | Meaning |
| --- | --- |
| `assessment`, `phase` | Frozen admission and initial/final/decision phase |
| `current_max_age_seconds` | Existing inclusive seven-day limit, 604800 seconds |
| `sources[].source_id` | An actually observed document ID |
| `sources[].date_options[]` | Allowed date-source ID, observed publication, age at admission, and legal time roles |
| `targets[].five_part[]` | Scope and at-least-one set for that symbol |
| `targets[].issuer_identity_evidence_ids` | Sources whose observed target-symbol metadata contains that symbol |
| `targets[].followup` | Existing question bound and eligible Fetch source IDs |
| `targets[].news_current_complete_options` | Current date/source combinations with complete presentation history |
| `rules` | Instructions explaining the unchanged semantic constraints |

The guide reports eligibility. It does not label evidence as primary, decide its
origin, choose an issuer name, determine sufficiency, choose a trade, or edit a
claim. Invalid guide input fails with the existing required-model failure path
before a request is sent.

For market, sector, chain, and plan, at least one evidence ID must belong to the
symbol and scope. Stock requires its own `md_` ID. A separate stock `fx_` ID is
not required. Ordinary claims can retain a displayed other-issuer source; issuer
identity and Fetch remain restricted to their existing ownership rules.

An omitted `date_source_id` is treated as null, exactly as in the existing
validator. A non-null ID is eligible only when it is the document's observed
same-URL `search_source_id`. Normal Search documents have no such parent and
cannot cite themselves. Unknown, naive, malformed, future, and older publication
timestamps cannot be current. Exactly 604800 seconds old remains eligible.
Background and unknown remain possible time roles; eligibility does not select
the model's interpretation.

Presentation history preserves a prior complete delivery if a later view is
partial. Each research request restricts guide IDs to the source IDs already
allowed by that request. Final decision uses the accumulated verified research
presentation history. The existing exact-quote validator still checks actual
displayed text.

## Schema and final decision

The new v4 builders start from the existing output shapes and append relations:

- Claims bind `source_id`, optional `date_source_id`, and `time_role` together.
- Each symbol's five sections must contain at least one eligible reference.
- Non-sufficient status requires a gap.
- News-event sufficiency requires the same current, completely presented source
  in both issuer identity and a primary claim whose origin equals that source.
- Initial `followup.needed=true` requires a bounded question or observed Fetch
  target; false requires both action fields null. Final and decision require false
  and null action fields.
- Decision row symbol, literal thesis symbol, and own market ID agree. Other
  symbols' market IDs remain unavailable in that row.

`decision_schema_v4(..., base_schema=...)` deep-copies the caller's existing
decision schema before appending these bindings. Existing source-owned fields,
required fields, and `allOf` clauses survive. This matters when another reviewed
decision contract is integrated later. The caller's schema is not mutated.

The normal final wire alias and same-symbol `reuse_thesis` path remain in place.
The guide uses the already recognized ID field names. Final output is decoded
before the unchanged no-new-claim, quote, issuer, sufficiency, numerical approval,
and paper-account checks. Reuse does not permit another symbol's thesis.

The local schema subset adds standard `contains` in four places: allowed
keywords, child-schema checking, matching, and safe mismatch location. Arrays
need at least one matching item; multiple matches are allowed. A non-array
ignores the keyword. Empty/boolean schemas and unsupported `minContains` or
`maxContains` remain rejected by the existing restricted subset. A failure reports
the array path and fixed keyword, without publishing a rejected model value.

JSON Schema defines this keyword in its [array reference](https://json-schema.org/understanding-json-schema/reference/array#contains).
The provider's [JSON Output documentation](https://api-docs.deepseek.com/guides/json_mode/)
describes valid JSON output, not server enforcement of this application schema.
The schema is visible in the model request and enforced locally on receipt. A
model can still return an invalid answer; the run must then fail normally.

## Verification and limits

`tests/test_research_request_contract_v4.py` exercises the three motivating
classes, time boundaries, invalid dates, same-URL Fetch attribution, scope and
ownership boundaries, news proof intersections, follow-up actions, empty batches,
legacy request bytes, preservation of every old input field, final wire decoding,
strict rejection paths, and complete request budgeting.
`tests/test_research_contains_schema.py` checks the schema-subset extension,
combinations, existing array checks, invalid schemas, concurrency, and safe
diagnostics. The exact original FULL16 projection is hash-bound and contains no
original statements, quotes, model reasoning, or source bodies.

Tests use synthetic transport and deny sockets. Local author tests establish
bounded implementation behavior. They do not establish provider reliability,
real business success, independent acceptance, main integration, deployment, or
future scheduled execution. Those require their own exact-source receipts.

No retry of a failed real run is part of this patch. No old receipt, account state,
failure history, execution identity, or source content is rewritten.
