### 1.2 代码现状（v6.3 拆解结论）

- **五环架构 17 环节**（`trading_system/pipeline.py`）：信息层（SearchHub+LLM 清洗）→ 数据层（行情降级链+零基线）→ 决策层（L0→L1 MRS→L2 SHS→L2b ICS→L3 TSS→L4 风控）→ 执行层（交易卡片/盘前计划/盘中触发器）→ 迭代层（journal→WFA→DSR）

- **运行方式**：`main.py --mode daily|premarket|intraday` + cron 定时（北京时间 06:00 美股收盘后）

## 2. 升级总架构：财神爷内核 + WorkLoom 治理外壳

```
┌──────────────── WorkLoom IM 底座（治理外壳，TS）────────────────┐
│ 五元事件库(哈希链留痕) │ 围栏引擎(白皮书阈值→block级基线)          │
│ Quest 任务循环(盘前/盘中/盘后/周末编排) │ night-shift 夜间守夜      │
│ 审批卡片(review级动作) │ 组织记忆(复盘沉淀) │ site 官网(责任界面)    │
│                          ▲ Quest 工具调用 / 事件回写                │
│ ┌──────────── 财神爷交易内核（决策核心，Python，完整保留）─────────┐ │
│ │ 17 环节管线 │ 六层决策栈(MRS/SHS/ICS/TSS/L4) │ SearchHub 6源   │ │
│ │ 行情降级链 │ journal→WFA→DSR │ 小G模拟盘 │ 双页签日报          │ │
│ │ 【注入】多空辩论证据层 │ 统计校准层 │ 三市 Market 抽象          │ │
│ │ 【注入】T0-T3 数据可信度 │ 摩擦成本三栏 │ A/H 数据主题          │ │
│ └──────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

**架构原则**：
1. **内核零改写红线**：财神爷的决策栈、阈值、风控公式一律以 `config.py` 为 single source of truth（白皮书附录"单一口径"），WorkLoom 侧不得另立第二套阈值——围栏规则从 config 生成，生成过程留痕。
2. **外壳只做治理不做决策**：WorkLoom 不产出任何交易评分；它负责把财神爷的每个动作变成"可追责的事件"（五元化留痕）、把白皮书红线变成"机器级保险的第二道锁"（围栏 block 级基线）。
3. **白皮书的 ExecutionTracer 与 WorkLoom 的 RuleImpact 双留痕**：进程内 17 环节点名不变；进程外每个动作记 RuleImpact，两本账可互相验真。

### 3.3 白皮书阈值 → 围栏三层结构（治理外壳的核心资产）

**生成纪律**：围栏规则从财神爷 `config.py` 自动生成（单一口径），生成记录进五元事件。

| 层 | 规则（白皮书出处） | 围栏级别 |
|---|---|---|
| **基线层（不可改）** | R-T1 结构止损触及必执行（D4）；R-T9 单票 >20% 净值（D4）；R-T10 MRS*<4 开新仓（D3）；R-T11 MRS*<6 且非轻仓条件按标准仓放行（D3）；R-T12 轻仓通道仓位未×0.3–0.4（D3）；R-T13 浮盈≥2R 未做盈利保护（D4）；R-T14 数据硬依赖全断仍产出报告（D2 诚实失败）；R-T15 17 环节缺环（D6） | **block**（触发即拒绝+P0 告警，仅作者可改代码级阈值） |
| **客户 patch 层（只可加严）** | 总仓位上限收紧（如 Gross Cap 70%→50%）；单票上限收紧（20%→15%）；r 收紧（0.8%→0.5%）；每日新开仓笔数上限 | review 可改，只许收紧（基线单调守卫） |
| **策略快照层** | 每张交易卡片的 Pin/Psl/分批/时间止损快照（附录C 模板） | 随信号审批绑定，盘中触发器严格执行 |
